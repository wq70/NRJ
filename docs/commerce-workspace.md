# 真实平台共逛

入口：一起吃 → 真实平台四个按钮；商城 → 真实平台，或已保存的受支持商品链接。

Android/iOS 使用独立 WebView，Vue 的角色面板保留在下方。网页版通过独立共逛服务使用真实浏览器，保留外部打开操作；没有 iframe 或假登录。网页部署与边界见 [commerce-web-deployment.md](./commerce-web-deployment.md)。

## 当前接通的链路

- 原生平台浏览、返回/刷新、新窗口导航、持久化平台 Cookie、平台/支付 App scheme 调起。
- 角色选择、可见页面文字读取、复用聊天 API 与角色人设、独立偏好和会话保存、建议按钮执行。
- 登录、验证码、支付和地址填写区域暂停读取；远程页面没有应用 Capacitor bridge。
- 建议执行前检查页面地址、目标元素、标签、覆盖层和是否重复执行。付款/提交订单等按钮不交给角色执行。
- 用户可保存已脱敏的当前页面观察摘要，按账号、角色、平台隔离；现有备份包括这些摘要和对话，不包括 Cookie。
- 原有剧情购物、钱包、购买标记、商城设置保持可用。真实记录与剧情订单没有互相转换。

## 环境与验证边界

原生代码需重新构建并安装应用，单独刷新网页不能加载原生插件。构建前使用项目现有 `mobile:sync` 流程同步前端资源。iOS 插件位于已加入 Xcode 工程的 SceneDelegate.swift 中，由 CommerceBridgeViewController 注册；Android 由 MainActivity 注册。

平台网页能否完成所有账号验证、WebView 是否被平台接受、支付后返回当前应用均需使用实际设备和账号逐平台验证。Cookie 持久化不代表会话永不过期，也不代表继承官方 App 登录。

页面记录仅证明本次读到的页面文字，不是官方订单 API 核验。没有接入四个平台的买家订单接口或后台配送推送。当前角色理解使用可见文字，不包含截图视觉识别、语音对话或对页面内跨域 iframe 的读取；平台结构不暴露语义按钮时需用户直接点击。

## 专项检查

`npx tsx scripts/test-commerce.ts`：URL 校验、敏感数据过滤、会话隔离、页面脚本执行、过期目标、重复点击和遮挡。

原生实机验收：四个平台分别验证登录/验证码、关闭重开、搜索/规格/加购、角色理解、支付取消与成功返回、订单页观察、网络失败、系统返回键、横竖屏/键盘/窄屏布局。网页 UI 检查不能代替这些验收。
